# AGENTS.md

Guidance for agents working in TradingJournal.

## Overview

TradingJournal is a Cloudflare Worker API + Vite React SPA (pnpm workspace) for recording personal A-share (A股) stock trading:

- **Trades**: every buy/sell execution with price, quantity, fees, strategy tag, and reason. FIFO matching computes realized PnL per sell.
- **Cash Flows**: deposits and withdrawals (出入金) that keep projected equity curves accurate.
- **Equity Snapshots**: optional manual daily account-total snapshots; the equity curve prefers snapshots and falls back to `initial_capital + net deposits + realized PnL` projections.
- **Analytics**: overview metrics, by-strategy/month/symbol breakdowns, equity curve, drawdown.
- **Backup**: manual full JSON/CSV export + `POST /user/import` idempotent restore; daily cron backs up all users to R2.
- **Multi-user**: identity comes from Cloudflare Access; `users` table upserted on first request; all queries scoped by `user_id`.

## Architecture

```
Layer 0: shared, backend-errors          — zero @trading-journal/* deps
Layer 1: backend-data                    → layers 0
Layer 3: backend-services                → layers 0–1 (not apps)
Layer 5: apps/api                        → layers 0–3
         apps/web                        → SPA, talks to API via /user/* and /api/*
```

**API app** (`apps/api/`):
- `src/index.ts` — exports `fetch`/`scheduled` via `TradingJournalWorker`.
- `src/workers/TradingJournalWorker.ts` — Hono routes, D1 session wrapping on `/user/*` and `/api/*`, SPA catch-all.
- `src/endpoints/` — file-routed route classes extending `IUserRoute`.
- `src/middleware/` — `MiddlewareHandlers.userAuthentication` resolves the Cloudflare Access user and injects `userId`/`AuthenticatedUserEmailAddress` context variables.
- `src/generated/spa-shell.ts` — generated by web build; do not edit.

**Web app** (`apps/web/`): Vite React SPA. `vite.config.ts` proxies `/api` → `http://localhost:8787` in dev; embeds `dist/index.html` into `apps/api/src/generated/spa-shell.ts` on build. Components: `ui/` (Button, Input, Card, Badge, Modal), `shared/` (Metric), `analytics/` (LineChart, BarChart, HorizontalBarList — hand-rolled SVG, no chart library), `views/` (TradesView, CashFlowsView, AnalyticsView, SettingsView, ExportView).

**Packages**:
- `shared/` — models, zod schemas, constants, `PnlMatchingUtil` (FIFO), `EquityProjectionUtil`, `CsvUtil`.
- `backend-errors/` — `ServiceError` hierarchy (`BadRequestError`, `UnauthorizedError`, `NotFoundError`, `ConflictError`, `InternalServerError` + `DefaultInternalServerError`, `DatabaseError`).
- `backend-data/` — D1 access via DAOs (`UserDAO`, `TradeDAO`, `CashFlowDAO`, `EquitySnapshotDAO`, `SettingsDAO`) + `D1SessionUtil`.
- `backend-services/` — `auth/` (`EmailValidationUtil`), `user/` (`UserService`), `trade/` (`TradeService`), `analytics/` (`AnalyticsService`), `backup/` (`ExportImportService`, `BackupService`).

## Bindings

- D1 `DB` (`trading-journal-db`)
- R2 `BACKUP_BUCKET` (daily JSON backups, retention `BACKUP_RETENTION_DAYS` default 30)
- Cron `30 1 * * *` (daily backup sweep)
- Vars: `DEV_AUTH_EMAIL` (local bypass), `POLICY_AUD` + `TEAM_DOMAIN` (Cloudflare Access JWT validation), `SERVE_SPA_FROM_WORKER` (default true)

`apps/api/wrangler.template.jsonc` is the template — copy to `wrangler.jsonc` per deployer; no committed `wrangler.jsonc`.

## Auth And Routing

- `/user/*` — Cloudflare Access; verifies `cf-access-jwt-assertion` JWT against `TEAM_DOMAIN`/`POLICY_AUD` (or `DEV_AUTH_EMAIL` locally), upserts the user, sets `AuthenticatedUserEmailAddress` + `AuthenticatedUserId`.
- `POST /api/backup/run` — public endpoint guarded by `BACKUP_TRIGGER_SECRET` header, triggers the backup sweep (R2).

**Protected (`/user/*`):**
`GET /user/me` · `GET|POST /user/trades` · `PUT|DELETE /user/trades/:tradeId` · `GET|POST /user/cash-flows` · `PUT|DELETE /user/cash-flows/:cashFlowId` · `GET|POST /user/equity` (POST upserts by date) · `PUT|DELETE /user/equity/:snapshotId` · `GET /user/analytics` · `GET|PUT /user/settings` · `GET /user/export` (`format=csv&table=...`) · `POST /user/import`

## A-Share Rules (shared/constants/AStockRules.ts)

- Buy quantity must be a multiple of 100 shares. Sell allows odd lots (零股) but each execution is still positive.
- Price limits (approximate reference, used for validation hints): main board (60xxxx/00xxxx) ±10%, ChiNext (300xxx) / STAR (688xxx) ±20%, Beijing (8xxxxx/4xxxxx) ±30%, ST ±5%. `getPriceLimitRatio(symbol)`.
- T+1: a sell on the same day as a buy of the same symbol triggers a warning (allowed for ETFs 51xxxx/15xxxx/56xxxx/58xxxx).
- Money is rounded to 2 decimals via `MoneyUtil.round2`.

## FIFO PnL (shared/utils/PnlMatchingUtil.ts)

Sells are matched against buys of the same symbol in chronological FIFO order. Per sell: `realizedPnl = Σ(sellPrice - buyPrice) * matchedQty - allocatedBuyFees - sellFees`. Buy fees are allocated proportionally to matched quantity; remaining buy quantity stays in the queue (current holdings). Excess sells (more than held) are clamped and reported via `excessQuantity`.

## Equity Projection (shared/utils/EquityProjectionUtil.ts)

For each date in the series, equity = snapshot if one exists, else `initialCapital + Σ(until date)(deposits − withdrawals) + Σ(until date) realizedPnl`. Drawdown computed from the merged series.

## Backup

- JSON export format: `{ "version": 1, "exportedAt": ISO, "user": {email}, "trades": [], "cashFlows": [], "equitySnapshots": [], "settings": {...} }`.
- Import is idempotent: per-entity upsert by primary key (snapshots conflict on `(user_id, date)`).
- `BackupService.runBackupForUser` writes `backup-{userId}-{YYYYMMDD}.json` to R2 and prunes keys older than `BACKUP_RETENTION_DAYS`.
